# HTML 阅读与导出规范

## 默认交付合同

用户未指定交付要求且输入材料没有实质疑问时，直接在对话中交付完整文字报告，并同时保存同名 `.md` 和 `.html`，无需先询问格式。Markdown 是长期纯文本原本，HTML 是完整内容的阅读与按需导出版本，不是摘要或宣传封面。年度 A/B 各自生成一对文件；B 必须仅从已审核的孩子版 Markdown 生成，不能读取状态/知识私有区混排。

PDF、PNG 是 HTML 的可选衍生成品，不属于默认独立交付物。默认只保留 HTML 内的两个导出按钮；只有用户明确要求独立 PDF、PNG 时才实际生成、检查并交付。用户明确指定其他格式、只要文件、先审阅或不归档时，按其要求执行，不用默认合同覆盖用户选择。

输入文件有影响分析的问题时，先澄清最少必要信息；可顺带用一句话说明默认交付为文字报告、Markdown 和 HTML，PDF、PNG 按需生成。文件无实质问题时直接执行，不能单独为了交付格式增加确认轮次。

报告仍标注提示词 v2.0；视觉层版本独立为 `renderVersion: 2.3.0`。排版修订不重分析孩子、不重复累计事件、不把表观修改算作新知识；只改呈现时不改状态或知识文件。

## 原稿编排

先在 Markdown 建立清晰的语义层次，再生成 HTML：报告标题用一级，主章节用二级，章节内的不同议题用三级，同一议题内确有并列事项时用四级，不跳级、不为短段落强加标题。日报保留规定主章节；例如孩子分析可按情绪、需求、安全问题、幻想分组，家长复盘可按做对的地方、回应调整、事实校准分组，实际标题随证据决定。

每段围绕一个意思。对话依据、可能的理解、可参考的回应适合分段呈现；同一议题有两段以上内容时用三级标题形成语义分组，同一议题内确有多个并列案例时再用四级标题。必要时用 `**对话依据：**`、`**可能的理解：**`、`**可参考的回应：**` 等短标签帮助扫读，但不能机械补齐不存在的内容。完整的替代说法可用标准 Markdown 引用块，保留引入语以免与真实原话混淆。关键句适量加粗，不整段强调。不得为了更短或更醒目删除原话、推断限定语、转写疑点、匿名边界或来源链接；不可把“可能”改成断言。

整理旧报告前备份原稿，保留全部分析内容与原意，对照整理前后的可见文字验证。生成器只负责排版，不修改输入；HTML 的原文下载必须与本次 Markdown 字节一致。新增小标题、拆段与强调使用标准 Markdown，不需要额外排版配置，也不使用原始 HTML 标签做高亮。

先完成并核验匿名化 Markdown，再运行随包生成器（Python 标准库即可）：

```text
python scripts/build_report_html.py "档案/D-2026-09-17.md" --headline "从同学的名字，聊到身边的安全。"
python scripts/build_report_html.py "档案/Y-2026-B-孩子的一年.md" --audience child
```

相对脚本路径以 skill 安装目录为准；档案路径按实际目录传入，建议绝对路径。未指定 `--output` 时生成源文件旁的同名 HTML。`--headline` 可选，须与该期证据相符，避免“焦虑孩子”“胜任感不足”等定性标题。可用换行控制封面标题，但不能改原文。生成器不修改 Markdown 或状态。

标题、列表、引用、表格、代码及来源链接均保留；日报三列表格转成完整时间线，不能删掉标签或转写限制。普通其他表格仍按表格呈现。原始 HTML 作为文本显示，主动链接协议受限；外部图片只保留文字引用，若报告需要图片，须另行实现本地内嵌并验证，不宣称图片已原样呈现。

## 视觉方向

以“私人珍藏书刊”为视觉方向：温暖的纸页、克制的出版物排版、安静的月窗插画。主色使用深灰蓝 `#263e4a`，强调色使用低饱和暖橙 `#b36a43`，纸底使用象牙白 `#fbfaf6`，浅层使用暖石灰 `#f0eee8`；不使用粉红、浅蓝等额外大面积语义底色。避开鲜艳颜色、厚重色块、大圆角、强阴影和无差别卡片堆叠。封面采用左侧加粗书名、右侧原创月窗插画与细书脊线，保留充足呼吸空间。优先使用本机华文中宋等中文衬线字体呈现标题，正文使用清晰的无衬线字体；不联网加载字体，不私自复制商业字体到 skill。

### 文字容器体系

保留大章节的开放式叙事排版，不把整篇改造成信息图。全页背景只使用三个固定层级：白色层、暖石灰浅色层、深灰蓝层。颜色顺序由内容深度决定，不因“安全、需求、成长”等关键词随意换底色；暖橙只作强调色，不形成第四种大面积底色。正文内部按阅读用途建立四层容器：

1. **普通正文层**：二级章节保持象牙纸面开放排版，无外框，依靠段距与留白连续阅读。
2. **议题分组层**：所有三级标题与其内容统一使用暖石灰浅色容器，1px 发丝边框、2–3px 小圆角，无阴影；一组只表达一个议题。
3. **内层内容层**：所有四级标题与并列案例统一使用白色内层容器；需要强调时只改变左侧发丝线宽度，不改变底色。
4. **核心强调层**：全篇阅读提要使用深灰蓝；页尾用同色完成收束。其他正文不使用整块深色，以免打断长篇叙事节奏。

禁止同类容器嵌套：浅色三级父层内只能放白色四级子层；四级子层中的完整引用必须使用透明背景，只保留 2px 暖橙竖线与缩进，不能再出现圆角、描边或阴影。独立引用使用白色容器和细边框。容器层级必须从底色、边界和留白一眼分辨，不能只靠尺寸变化。

今日金句和对话时间线使用白色容器；姿态建议整组使用一个浅色容器，各条之间用 1px 发丝线分隔，不再重复堆叠卡片。容器必须由报告已有的标题、引用、列表或表格结构触发，不改写正文，也不自动增加分析结论。重要性通过标题字重、编号、暖橙竖线与留白表达，不通过新增底色表达。旧报告标题较少时保留开放式正文，不强行制造容器。

取消附着在文字上的下划线视觉：来源链接不使用 `text-decoration: underline`，改用暖橙字色、字重和外链箭头；四级标题不用底部横线；加粗首句不用荧光笔式底纹线；原稿下载入口也不加下边线。表格行、封面、章节与页尾中真正承担分区作用的结构线可以保留。

内容按阅读用途分层：对话记录用“左侧时间、右侧叙事卡”的书刊式编排；金句与解释在桌面并列，在手机自然上下排列；三级标题用暖橙短竖条引导并与所属内容形成分组容器；四级标题依靠字号、留白和内层容器分级，不使用标题底线。阅读提要的装饰标签随日/周/月/年类型变化，不把周报或年报误标成“今夜”。这些排版不增删原文。家长报告不做儿童玩具风或临床量表界面；不为戏剧效果放大风险。

正文桌面 17px、手机 16px，行高约 1.9；金句解释 16px，辅助信息 11–13px。一级封面标题显著加粗（700），桌面 38px，手机根据宽度在 27–32px 自适应；主要章节标题同样加粗，桌面 27px、手机 25px。打印正文 11pt，保留粗体大标题；用留白和层次建立精致感，不以缩小正文换取页数或图片数量。

默认只在报告最底部署名一次（用户可修改或移除可见署名；代码许可信息须保留，见根目录 LICENSE 与 THIRD_PARTY_NOTICES.md）：**作者：阿昌 丨 公众号：阿昌正传**；封面不署名。署名独立一行居中，上方用细分隔线与留白隔开正文及版本信息，颜色浅于正文（柔和灰棕），常规字重，桌面 12px、手机 11.5px、打印 8.5pt。署名是整页最后的静态可见文字，并随 PDF、PNG 保留。

同步检查 Markdown：标题、段落或文字内容变化须相应整理原稿；字号、配色、响应式布局和出版署名由模板负责，不向 Markdown 强行写入 CSS、HTML 或重复署名。Markdown 保留标准一级标题及二至四级层次，生成的 HTML 与本次原稿全文一致。旧报告没有小标题时仍能完整显示；不得自动编造小标题或新分析。

桌面侧栏导航，手机单栏，目录可横向滚动，原稿下载在手机上仍可用；首页仅保留“另存为 PDF”和“另存为 PNG 图片”两个导出按钮，不显示静态导出操作说明或“离线可用”等技术提示。需要的说明只在点击按钮后出现。保留 viewport 设置，标题、间距和按钮适应 320px 及以上屏幕，不禁用用户缩放；正文和页面无横向溢出，仅目录区域允许横向滚动。按钮、目录和操作提示不进入导出正文，不默认折叠关键内容。

## 导出行为

- PDF：按钮调用浏览器原生打印，点击后才提示选“另存为 PDF”。使用 A4 打印 CSS，隐藏工具栏，保留可搜索文字、来源链接和完整正文；检查分页、段落孤行、标题与下文、表格行与引用，不能声称单击即自动下载 PDF。
- PNG：一次操作只保存**一张完整 PNG**，文件名为报告编号，无分片编号。按 900 CSS 像素宽、2倍分辨率导出。html2canvas 内部使用小画布逐条渲染，再由随包 `png-encoder.js` 顺序写入同一 PNG；不建立超高整页画布，不因超过画布高度上限而分成多张，不缩小正文或丢掉结尾。
- PNG 编码优先使用浏览器原生 CompressionStream；不支持时使用内置无压缩 zlib 回退，仍然只输出一张完整图片。导出失败应明确报错并允许重试，不静默交付残图或多张图片。
- HTML 自包含 CSS、JavaScript、Markdown 原文及渲染库，`file://` 双击可用，不依赖 CDN、远程字体、服务器或在线截图服务。不得为排版把儿童档案上传外部服务。
- 导出中的按钮禁用并显示进度；失败显示可操作提示，不假报成功。重复导出不累计页面副本。移动端导出仍使用统一阅读宽度。

## 分级交付验收

验收范围跟随本次实际交付物，不把可选导出检查强加给默认报告：

1. **每次默认 MD+HTML 交付**：对照源 Markdown 验证标题、正文、原话、表格单元与来源链接都在 HTML 中；下载原文须与输入字节一致，并确认 HTML 无外部资源依赖。整理原稿时另与备份核对，确认只改层次、断段与强调，状态和知识未因排版重复更新。
2. **模板未变化的日常报告**：运行生成器的快速结构与内容检查，确认报告编号、内嵌原稿、哈希、自包含资源和基本 HTML 结构正确。无需为每份新报告重复全部视口、长图和打印回归。
3. **模板、样式、生成器或导出代码变化**：重新生成代表性短报告与长报告，在真实浏览器检查桌面、320/375/390/430px 手机宽度及横屏；检查标题、正文、底部唯一署名、目录、原稿下载、按钮、页尾、横向溢出和离线运行。按受影响范围执行 PDF、PNG 完整回归。
4. **用户明确要求独立 PNG**：实际导出一次并确认只生成一张完整图片，核对宽高、首尾、内部接缝与底部署名。修改编码器时运行 `node scripts/test_png_encoder.cjs`，并验证长报告和重复导出。
5. **用户明确要求独立 PDF**：实际进入打印流程并生成 PDF，检查全文可提取、分页清晰、标题不孤立、无内容丢失或空白溢出页。不得用按钮文字存在代替成品验证。
6. 默认新增报告须将 MD+HTML 都成功落盘后视作完整交付；若有一路失败，在状态存档备注写明缺失。用户明确改变交付或归档范围时按约定判定，但不把草稿提前标记为 processed；补格式不重复添加 processed 或里程碑。

用户要求打开成品时，打开实际生成的阅读版和所在档案文件夹，并只提供本次约定交付物的链接。PDF 与 PNG 仅在用户明确要求且实际测试生成后保留同目录供直接使用。校验截图和中间页图放独立测试目录，不混进长期档案。

## 随包资源

`assets/web/` 包含模板、样式、渲染器、原创月窗 SVG 和单图 PNG 编码器。生成器把插画和全部代码内嵌进 HTML，不能留下相对资源路径。`vendor/` 含 Marked 17.0.5（MIT）及 html2canvas 1.4.1（MIT），对应许可证同目录保留。HTML 内嵌库保留其许可注释。更新依赖后须重新进行离线、导出、内容安全测试；日常使用无需联网安装依赖。
