# 运行与记忆协议

## 周五锚定历法

一周从周六至接下来的周五，周五为锚点。周归属于锚定周五的公历月份和年份；月由其全部锚定周五对应周报组成，不按自然月裁剪日报。月内最后一个周五对应最后一份归属周报。

周标识使用锚定周五的 ISO 周年和周号 `YYYY-WXX`，报告加前缀 `W-`。**周编号中的 ISO 年与月/年归属的公历年分开计算**：原文未明示 ISO 跨年编号细节，此处统一采用标准 ISO 周年避免歧义，不更改其“周五决定月年归属”的规则。

- 2026-08-29 至 2026-09-04 → `W-2026-W36` → 2026-09。
- 2026-12-26 至 2027-01-01 → `W-2026-W53` → **2027-01 / 2027 年**。
- 2027-01 的五份周报是 `2026-W53`、`2027-W01`、`2027-W02`、`2027-W03`、`2027-W04`。不能按编号年份过滤年度材料。

数据日期用于年龄与归属；`last_updated` 是实际修改文件的日期。初次启用中途开始的周/月/年，列出未覆盖范围并确认是无对话还是无资料，标明部分周期，不把“未提供”当成“无对话”。

## 输入与历史校验

1. 优先加载本次指定的档案，先读家长备注；已有档案不得用空模板覆盖。[空状态模板](../assets/state-template.json) 和 [空知识模板](../assets/knowledge-template.json) 仅用于新建，使用时将 last_updated 的 null 替换为实际日期，填已知路径，未知路径留空。
2. 日期已在 `processed.daily`：若未明确要求重做，询问是否重新分析。家长已明确“重做该日报”时直接按修订处理。
3. 日期位于 `pending_confirmation`：说明曾标缺失并确认继续；家长已明确“补录该日”则不重复询问。成功归档后清理对应待确认项。
4. 检查已处理的相邻日期与新日期之间空缺；无历史时不倒推所有未记录日。列清单询问“待补生成/确实无对话”。可先完成不依赖缺失数据的当晚报告，将未知缺失保留为 `missing_unconfirmed`。
5. 上级报告前列出所需全部下级报告、已有材料、缺失及确认状态。有 `missing_unconfirmed` 则暂停上级汇总。确认无对话的日子记 `missing_confirmed`；没有整周/月文件不等于整期无对话，须核实范围。
6. 家长明确只做材料不全的阶段报告时，可产出注明覆盖区间的部分报告，但不伪装成完整周期、不据此自动触发完成链。没有任何有效下级材料时不编造分析报告。
7. `processed` 只证明曾完成并归档，不能替代报告正文。读取历史失败时请求手动提供，不按编号编造内容。
8. 批量输入按对话日期先后处理。补录较早日期不回退 last_updated 或清空较新进度；受影响的已存上级报告列为待修订，不静默重写历史。

材料完整、日期与人物明确、匿名化和转写不影响判断时直接分析，不为交付格式增加确认。材料存在会影响结论或归档的实质疑问时，只询问必要问题；可在同一条澄清消息末尾简要说明默认交付为文字报告、Markdown 和 HTML，PDF、PNG 按需生成。用户对交付、审阅或归档有明确要求时优先执行该要求。

## 升级调度与确认

完成本级后说明下一层条件及所需档案，让家长选择手动提供或通过**已接入且可用**的存档工具获取。等待其选择再继续；已有明确授权可直接落实，不反复索要同一确认。

周五没有对话时不伪造周五日报。只有家长确认无对话并明确请求周报，且其他材料状态已核实，才按覆盖说明汇总。月年缺期同理，不自行跳过完整性检查。

## 状态文件

基于空模板保留并更新完整结构，不仅输出变更片段或省略旧记录：

| 字段 | 约定 |
|---|---|
| `prompt_version` | 当前 `v2.0`；旧报告保留旧版本 |
| `last_updated` | 实际更新日期，`YYYY-MM-DD` |
| `processed.daily/weekly/monthly/yearly` | 去重、有序的周期标识；不含 D/W/M/Y 前缀 |
| `pending_confirmation` | `{date, type, status}`；type 为 daily/weekly/monthly/yearly，date 为对应周期标识；status 为 missing_unconfirmed/missing_confirmed |
| `sediment.red_flags/watchlist/repair_debts/milestones` | 红旗、观察点、修复债、里程碑，见下 |
| `archive.local_path/cloud_path/notes` | 实际档案位置与存档状态；未知留空，不填 API 占位字符串 |
| `notes` | 必要的工作说明，不混入未经确认的长期知识 |

### 沉淀记录

- 红旗：`{id, type, status, first_seen, evidence, count, resolve_criteria, notes}`。id 如 RF-001；evidence 是报告编号，count 是**独立发生次数**，不是报告数量。
- 观察点：`{id, topic, source, status, review_by}`。id 如 WL-001，status 为 active/closed；到期给续期/关闭建议，不因时间过去自动认为问题消失。
- 修复债：`{id, incident, source, status}`。id 如 RD-001，status 为 unpaid/repaired；可加 `repair_source`/`repaired_on` 记录明确修复证据。提出建议不等于已修复。
- 里程碑：`{date, event, source, starred}`。AI 候选默认 starred=false；家长选中或已明确标⭐才设 true。同事件不重复创建。

唯一 id 延续已有最大序号。同日多个独立事件用定位如 `D-2026-09-04#片段2` 区分。需要精确去重时可在红旗增加 `occurrences`，每项含稳定 id、date、source、片段位置与必要短引文；不复制整段敏感对话。

同事件被日/周/月报引用仍只计一次。重做先替换该日报的证据贡献再重算，不能直接 count += 1。旧状态无事件明细时保留历史 count，说明依据受限，不擅自归零或猜测重复。历史不明重复由家长确认后纠正。

生命周期：observing → resolved（满足条件且**家长确认**）或 escalated（证据加重，报告置顶）。自否累计 1–2 次可作为 observing 候选记数，notes 标“未达三次阈值”；满 3 次才声明达到 `🚩自否` 触发阈值。解除后再次出现独立新事件可重开观察，不抹去过去记录。

“连续 14 天无新证据，或家长确认已化解”是原文示例，不能硬编码为所有红旗通用门槛。无记录、数据缺失不代表已观察到风险消退；期满只产生解除建议，不能自动 resolved。可加 `history` 数组记录状态变化日期、旧/新状态、依据和确认来源，供年度全史使用；保留已解除条目。

### 红旗建议与日报禁探询

普通日报不夹带“明天问问”的任务。原文红旗区允许例外的温和探询，仅在真实红旗需要澄清或保护时，放在红旗区，说明必要性、不诱导、不对质、不让孩子觉得被监控。不得把常规话题包装为红旗来绕过禁令。

若材料显示即时危险或严重身体伤害，优先说明即时保护/就医或寻求专业支持的必要性，不让“周报再探询”阻碍安全行动。以具体证据为限，不作心理或医疗诊断；需要具体医疗指导时使用当前可靠专业来源。

## 知识文件

知识分区：

- `transferable.child_dictionary`：`{entry, meaning, confirmed, source, status}`。
- `transferable.traits_and_preferences`：`{entry, confirmed, source, status}`。
- `private.parent_hook_profile`、`private.sensitive_map`：同样记录条目、确认日期、来源、状态。

status 为 active/expired。confirmed 是实际家长确认日期，不回填为首次发生日。应用词典时注明有效条目，仍结合当晚上下文，不机械判定。

AI 周报提名 0–3 条 → 家长确认/修正/否决 → 仅写入确认后的内容。未确认提名留在周报或工作待办，不提前写入知识；否决后不写入知识，也不另存否决档案。不能由此擅自删除已归档报告。明确“记住……”等直达指令就是写入确认。

不删旧条目。家长确认修正已存知识时，将旧条目标记 expired 并追加新条目；可加 id、expired_on、supersedes 保存演变。AI 认为过时只能建议。没有本次确认改动，不重发或改写知识文件。

移交前只导出 transferable 的适合内容，仍检查尊严与羞耻风险；区域名不等于每条自动适合回忆录。private 永远不进孩子的文件、共享包或对质话术。模板数组为空，原文的“随便”“还行”和家长钩子举例不是已确认家庭事实。

## 纯文本原本、HTML 阅读版与双存档

| 内容 | 文件名 |
|---|---|
| 日报 | `D-YYYY-MM-DD.md` + 同名 `.html` |
| 周报 | `W-YYYY-WXX.md` + 同名 `.html` |
| 月报 | `M-YYYY-MM.md` + 同名 `.html` |
| 年报 A | `Y-YYYY-A-年度发展评估.md` + 同名 `.html` |
| 年报 B | `Y-YYYY-B-孩子的一年.md` + 同名 `.html` |
| 最新状态 / 知识 | `STATE-latest.json` / `KNOWLEDGE-latest.json` |

年度 A/B 共用 `Y-YYYY` 报告族编号，加后缀防覆盖。可导出 `KNOWLEDGE-transferable-YYYY.json` 年度快照，绝不能用完整知识文件冒充可移交快照。

默认在对话中展示报告全文，具备文件工具时同时提供 Markdown 与同名 HTML。HTML 首屏包含按需使用的 PDF/PNG 导出按钮，按 [HTML 交付规范](html-delivery.md) 生成和分级验证；默认不另行生成 PDF、PNG 文件。用户明确指定格式或要求“只要文件”“先审阅”时按其要求执行。Markdown/JSON 仍是可迁移的长期原本，HTML 不替代它们；状态和知识 JSON 作为运行档案更新，不作为常规报告成品反复交付。年度 B 的 HTML/PDF/PNG 只能由孩子版原文生成，不能读取私有档案填充。

本地路径已明确并授权时执行保存；路径未知则请求路径或交付手动保存内容。云端只有已配置、获授权且成功执行才算完成，否则明确“待手动云存档”。`TRANSCRIPTION_API`、`ARCHIVE_LOCAL_API`、`ARCHIVE_CLOUD_API`、`FETCH_API`、`STATE_API`、`KNOWLEDGE_API` 是能力位，不是现有工具。

`processed` 不在只生成草稿时提前追加：默认交付下，报告的 MD+HTML 已保存到至少一个持久档案位置或家长确认手动保存后才记录，在 `archive.notes` 明确另一路是否待补存。用户明确改变交付或归档范围时遵从其要求；只有正式原本已按约定持久保存时才标记 processed，用户明确不归档时不得标记。缺少约定格式时明确待补，不伪称完整交付。旧报告只补格式时保留既有 processed，不重复累计证据。正式文件均未落盘时用可选 `pending_archive` 列出本次已生成但待保存的编号和目标。上级处理可基于本次正文，但仍须授权与覆盖检查。补存成功清除对应待办。

保存状态前验证 JSON 可解析，保留未知兼容字段；对已有文件使用临时文件写入后替换，失败保留原件。报告、状态、知识存档结果一致；云端建议保留历史版本，部分失败只重试失败项。重做保留可追溯修订或备份，不覆盖无关文件。

## 长期运行提醒

- 家长可对关键转折、金句、重要事件标⭐，同步里程碑。
- 行为调整以周为节奏，知识提名确认是每周核心互动，不增加孩子的任务。
- 每季度可抽一份日报对照家长记忆校准 AI，校正走知识直达通道。
- 年末提醒冷备份；年度流程按年龄提醒 8 岁、10 岁录音授权重签与规则适配评估。
- 提示词真正升级才改版本，旧报告不回溯重写；不能仅因 skill 打包就改 v2.0。
- “每日”“周五”是报告规则，不意味着创建定时任务；仅在家长明确要求时配置实际自动化。
